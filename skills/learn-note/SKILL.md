# learn-note — 学习笔记沉淀

## Overview

把一次问答或一份外部材料，压缩成 Obsidian 知识库里的**一个条目**。

核心原则：**笔记 ≠ 对话转存**。对话是为了让人一路读下去，笔记是为了让人三秒内回忆起来。同一个知识点，两者该有不同的结构。

## 落点（固定，不要即兴决定）

笔记根目录（下称 `cc_notes\`）：

```
<VAULT>/study_note/cc_notes/
```

> ⚠️ **首次使用前先把这个占位符换成本机的真实路径。** 下文所有 `cc_notes\` 都指它。

| | 位置 |
|---|---|
| 主题文件 | `cc_notes\<领域>\<子类>\<topic-in-kebab-case>.md` |
| 索引 | `cc_notes\INDEX.md` |
| 主题分类表 | `cc_notes\TAXONOMY.md` |

**目录约定**：第一层 = `TAXONOMY.md` 里的「领域」列；第二层 = 子类；**文件名不带领域前缀**（文件夹已经表达了领域）。领域文件夹不存在时**先建它**，并把路径补进 TAXONOMY。

⚠️ **改文件名会断开所有 `[[双链]]`**（Obsidian 按文件名解析，跨文件夹）。改名前后必做两项检查：

1. **新名在全 vault 内唯一** —— `find . -name "<新名>.md"`。别处有同名会让 `[[双链]]` 变歧义
2. **没有来自 `cc_notes\` 之外的入链** —— 否则那些链接会断

改完**必须跑死链检查**：把所有 `[[目标#锚点]]` 拆开，验证目标文件存在、锚点标题存在。

**这个目录应该在代码仓库之外。** 它不是代码，是知识库——刻意和源码分开。**不要**把笔记塞进代码仓库下的任何目录。

Obsidian 状态：`cc_notes\` 需要位于一个**已注册的 vault** 内。这样才能用上 `[[双链]]`、标签面板、反向链接。

同一 vault 内可以和其他笔记目录互链（Obsidian 按文件名解析，跨目录也能链），例如：

```
<vault>\
├─ <其他笔记目录>\   ...
├─ <其他笔记目录>\   ...
└─ study_note\cc_notes\   ← 我们写在这里
```

## 流程

1. **取素材** — 对话模式回看本轮问答；投喂模式用给定材料（截图/PDF/博客/散装问题）。
2. **拆条目** — 一个问题 = 一个条目。同一轮里若出现了**独立且跨主题**的另一个概念，主条目放主主题，另一个概念在它的主题文件里只开一行 `[[链接]]` 占位。同一主题内的子概念不开占位——那是主条目正文该覆盖的内容。**占位的判定依据是"本轮讨论里真的出现过"，不是模板里有什么。**
3. **定主题** — 先读 `cc_notes\TAXONOMY.md`（它是分类的唯一权威，含每个文件的覆盖范围和 frontmatter tags）；再 `Glob cc_notes/*.md` + `Grep` 关键词，判断该**新建主题文件**还是**追加条目**。
   - 归类决定**必须报告**（"归到 `<某主题文件>.md` 了"），方便用户一句话纠正。不要问，问的成本太高；但要让决定可见。
   - **TAXONOMY 里找不到合适领域时，不要即兴造文件名。** 先用最接近的现有领域归入并报告"TAXONOMY 里没有 X 领域，暂归到 Y，要不要给 X 单开一行？"，把决定权交给用户。领域是慢慢长出来的，不是每次提问都长一个。
4. **写条目** — 双层模板，见下。
5. **更新 `INDEX.md`** — 条目数与标签表由 `Glob`/`Grep` **实算**，不要累加。
6. **报告** — 写到哪、新增还是合并、合并时补了什么、本次是否引入新标签。

## 条目模板（双层）

上层是速查卡，服务于"扫一眼就回忆起来"；下层是正文，服务于"想不起来了才展开"。

```markdown
# <领域名>

## <一个具体问题，写成问句> #<细标签> #<细标签>

> **速查**
> - <断言：能独立成立的一句话>
> - <断言>
> - <断言>
> - <断言，比如一条反直觉的边界或代价>

### 正文

**① <为什么会有这个问题>**
…

**② <机制本身>**

| 对比项 | A | B |
|---|---|---|
| … | … | … |

**③ <边界与代价>**
…（什么情况下这个结论不成立）

### 自测
- [ ] <能自测理解程度的问题>
- [ ] <问题>
```

**速查卡**的形态是：**不超过 5 行，每行一个能独立成立的断言**。写不出 5 行说明这个知识点还没有结论，回去把它想清楚再写。超过 5 行说明没有压缩，那是转存。

**正文**保留推导、代码、对比表、边界讨论；去掉对话里的寒暄、铺垫、重复、以及"好问题"这类填充。

优先复用对话中已经产出的结论和洞察块——它们天然就是速查卡的形状，不要重新发明一遍。

### 写作风格四条

**① 少用比喻。** 比喻可以用来开场建立直觉，但**比喻之后必须跟机制本身**。
好的比喻句好记，却往往没说系统具体做了什么——笔记的价值恰恰在后者。
判断标准：**读者只记住比喻，这条笔记就是失败的。**

反例：
> 垃圾回收器像一个清洁工，在后台默默打扫房间。

正例：
> 标记-清除 GC 分两个阶段：① **标记**——从根集合（栈、寄存器、全局变量）出发
> 遍历所有可达对象并打标；② **清除**——扫描堆，回收未打标的对象，并把存活对象
> 搬到一侧以消除碎片。
> 根集合由谁提供？**是编译器**：运行时无法从一段内存字节判断它是不是指针，
> 所以编译器在生成代码时额外写了一份栈映射表（stack map），运行时照着它去栈上
> 认指针。GC 本身是运行时的活，但"哪里是指针"这个信息只有编译器知道。

**② 专有名词首次出现时一句话解释。** 不假设读者记得任何缩略语或内部术语。
给「它是什么 + 属于哪一层」，一句话，不展开成段，也不要等用了三遍才解释。

反例：
> COW 之后，如果 TLB 没被刷掉，就会读到旧数据。

正例：
> **COW**（copy-on-write，写时复制：`fork` 后父子进程先共享同一份物理页，
> 谁先写谁才真正复制一份）之后，如果 **TLB**（translation lookaside buffer，
> CPU 里缓存"虚拟地址→物理地址"映射的小表）没被刷掉，就会读到旧数据。

**③ 明确标注「软件处理」还是「硬件支持」。** 讲一个机制时，把它的各部分按归属标出来：
哪些是软件（内核 / 驱动 / 用户态库在定策略、填参数），哪些是硬件能力（有电路在做这件事）。
绝大多数机制是"软件填参数 + 硬件执行"，**两半都要写出来**，不要让读者自己猜。

特别要区分**拥有能力**（硬件）和**使用能力**（软件）——这两件事经常被混为一谈。

反例：
> 现代 CPU 都支持虚拟内存。

正例：
> **支持虚拟内存是硬件能力**——芯片里有一块 **MMU**（memory management unit，
> 内存管理单元）专门做地址翻译：拿虚拟地址去查页表，得到物理地址。
> **建立映射是软件工作**——内核负责分配物理页、填页表项、并把页表基址挂到
> 控制寄存器上。
> 两者缺一不可：没有 MMU 的芯片，内核把页表填得再对，CPU 也不会去查它——
> 这不是"没优化"，是"用不了"。

**④ 讲公式/机制时，别停在"是什么"和"由××可得"。** 要给**让这个形式变得必然的实例**——能当场
数出来的、能验算的。**反例也要给**：用别的形式**当场失败**的。**"由某定理可得"不是解释，是引用。**

反例：
> 加速比 `S = 1 / ((1−p) + p/s)`（由 Amdahl 定律）

正例：
> 一段程序有 90% 的部分能并行（`p = 0.9`），给 9 个核（`s = 9`）：
> `S = 1 / ((1−0.9) + 0.9/9) = 1 / (0.1 + 0.1) = 5` 倍。
> 把核数拉到无穷：`S → 1/0.1 = 10` 倍——**这就是那个串行的 10% 定死的天花板**。
> 换个候选公式 `S = s × p` 试：`9 × 0.9 = 8.1` 倍——比 5 大得多，而且核数无穷时
> 它会发散到无穷，跟"串行部分定死上限"这个结论**当场矛盾，失败**。

判断标准：**读者读完能自己动手验一遍**，而不是只能相信你。

> ⚠️ **这类"为什么非这样不可"的内容，公式推导可以省，实例不能省。**
> 只给约束和结论、不给能验算的例子，等于没讲。

### 模板之外还必须有的四样

**① 主题文件顶部的 `# 标题`** — 每个主题文件的第一行是 `# <领域名>`，名字取自 `TAXONOMY.md`。条目统一从 `##` 起。

**② frontmatter** — `tags:` 的值**直接抄 `TAXONOMY.md` 分类表的 `frontmatter tags` 列**，一个字都不要改，更不要另造。粗粒度放这里，细粒度放条目行尾的内联标签。

**③ `相关：` 行** — 只在本轮讨论**真实提到过**其他主题的概念时才写，格式 `相关：[[主题文件#条目标题]]`，放在正文末尾、`### 自测` 之前。没有真实关联就**整行省略**。

> 示例模板里不写 `相关：` 行，就是为了防止照抄。**模板里的任何链接都不要直接抄进笔记** —— 只链接真实存在的条目。

**④ 自测块** — 每个条目末尾一个 `### 自测` 小节，附 2–4 个自测问题，用 `- [ ]` checkbox。这是"八股速查"的复习入口，不是可选项。

## 标签纪律

标签系统唯一致命的失败模式是**词表爆炸**：`foo` / `Foo` / `FOO` 三个标签指同一件事，三个月后按标签筛出来的还不如 grep 准。

三条硬规则：

1. **先 Grep 再建。** 写任何标签前先跑下面那条 grep 看已有词表，能复用就复用。不允许凭印象造新标签。
2. **新标签必须报告。** 本次若引入了词表外的标签，在收尾报告里单列（"新增标签：`#<tagname>`"）。
3. **`INDEX.md` 里的标签表由实算生成**，不手工维护。标签总数超过 ~30 个时提示用户收敛。

粒度分工：`frontmatter` 的 `tags:` 放整篇的粗粒度主题，条目行尾的内联 `#tag` 放该条目的细粒度知识点。

**统计口径（别猜）**：标签表只统计**主题 `.md` 文件里条目行尾的内联 `#tag`**。

**四个必须排除的**：

- **`frontmatter` 不算** —— 文件级元数据，计进去会让同一主题的每个条目都虚增一次
- **`INDEX.md` / `TAXONOMY.md` 本身不算** —— INDEX 里就有一张标签表，把它算进去会导致**每更新一次索引、每个标签计数就 +1**，越滚越离谱
- **`[[双链#锚点]]` 和行内代码里的 `#` 不算** —— `[[某主题#某条目标题]]` 里的 `#某条目` 是**锚点不是标签**；`` `#include` `` 同理。不去掉这两类会凭空造出假标签（实测踩过：中英文锚点被当成标签，还因为大小写不同和真标签并存，看起来像"词表爆炸"）
- **`#数字` 编号** —— 正文写 `步骤#1`、`C#2` 这种。⚠️ **这一类和上面三类性质不同：前三类是 grep 的假阳性，Obsidian 不会当标签；而 `#数字` 是 Obsidian 真的会当标签，污染标签面板。** 所以发现后要**改源文件**（改成 `(1)` / `(2)` 或 `①②`），不是改统计命令

```bash
cd "<VAULT>/study_note/cc_notes"
for f in *.md; do
  case "$f" in INDEX.md|TAXONOMY.md) continue;; esac
  sed -e 's/\[\[[^]]*\]\]//g' -e 's/`[^`]*`//g' "$f"
done | grep -oh '#[[:alnum:]_-]\+\|#[一-龥]\+' | sort | uniq -c | sort -rn
```

> 上面这条 `for f in *.md` 只覆盖根目录。笔记按 `<领域>/<子类>/` 分了两层时，
> 换成 `find . -name '*.md'` 遍历。

注意 `#[a-z]` 这种写法会漏掉中文标签，必须用上面这条。

**自检（必做）**：算完之后拿一个标签人工核对，例如

```bash
# 拿标签表里任一标签，数一下带它的条目行
grep -hE '^## .*#<某标签>( |$)' $(find . -name '*.md' ! -name INDEX.md ! -name TAXONOMY.md) | wc -l
```

应等于标签表里该标签的计数。对不上说明命令又漏了某类假阳性。

> ⚠️ **用 `( |$)` 收尾，别用 `\b`。** 词边界在 `#log` 和 `#logging` 之间也算成立，
> 会把带连字符或更长后缀的标签一起数进来（实测踩过：`#memory` 把 `#memory-model` 也数了）。

## 重复问题怎么办

同一个问题被问第二次时：**合并，不新建、不覆盖。**

- 定位已有条目 → 补充缺失的点 → 报告"补了 X，原有 Y 保留"
- 只有结论**冲突**时才改原文，并把旧结论降级成一句注记，不要直接删掉
- 判断"同一问题"看标题语义，不看字面

这是"长期知识库会回查"的隐含要求：一个主题被问三次，应该得到**一条越来越好的条目**，而不是三条互相矛盾的。

**"相关但新的追问"不算重复。** 判定标准是问的是不是**同一个问题**，不是问的是不是同一个话题：

| 已有条目 | 新问题 | 处理 |
|---|---|---|
| `<X> 是什么` | `<X> 是不是一定比 <Y> 好` | **新条目**（同一主题文件内 append） |
| `<X> 是不是一定比 <Y> 好` | 再讲一遍 `<X>` 为什么好 | **合并**进已有条目 |
| `<X> 是什么` | 那 `<相关概念 Z>` 呢 | **新条目**（若 TAXONOMY 把它划在同一领域，就不开占位，直接同文件 append） |

拿不准时**新开条目**——合并错了会污染已有笔记，新开错了只是多一条，成本不对称。

## INDEX.md 格式

```markdown
---
tags: [index]
updated: YYYY-MM-DD
---

# 笔记索引

## <领域>
- [[<主题文件>]] — <一句话覆盖范围，用 / 分隔> · N 条 · YYYY-MM-DD

## <领域>
- [[<主题文件>]] — <覆盖范围> · N 条 · YYYY-MM-DD

## 标签
- `#<tag>` — N 条
- `#<tag>` — N 条
```

首次写入时，**删掉 `## 待填` 占位段落**，换成正式分类。标签为 0 时保留 `（空）` 一行。

> 索引里的条目数与标签数**一律实算**，别手改、别累加——否则索引会和实际漂移，
> 而漂移是静默的，等你发现时已经对不上了。

## Obsidian 的三个坑

1. **标签大小写敏感** — `#foo` 和 `#Foo` 是两个不同标签。这就是"先 Grep 再建"不是洁癖而是防错的原因。
2. **正文里的 `#` 会被吞成标签** — 写 `#include`、`#define`、`#1` 编号时会被 Obsidian 当成标签解析。对策：代码一律进代码块**或反引号**（两者都不做标签解析），正文编号用 `(1)` 而非 `#1`。
3. **`[[文件#标题]]` 能精确链接到某一条笔记** — Markdown 链接只能指到文件，这条能指到条目。跨主题引用一律用它。

## 主题文件拆分

**不要按行数拆分。** 文件长不是问题。

拆分的**唯一**理由是**检索**：一个文件被两类互不相干的问句回查时，才按子领域切开，让文件名能命中其中一类。除此之外就让它长，条目在同一个主题文件里累积即可。

## 常见错误

| 错误 | 实际 |
|---|---|
| 把整个对话拷进去 | 那是转存。速查卡 ≤5 行是硬指标。 |
| 即兴决定笔记存哪 | 落点是固定的：Obsidian vault 里的 `cc_notes\`。不要塞进代码仓库下的任何目录。 |
| 一题一个文件，不建主题文件 | 知识点会互相孤立。相关概念必须住在同一个主题文件里才能互相看见。 |
| 凭印象造标签 | 先 Grep。词表一旦爆炸就救不回来了。 |
| 用户没要求就写文件 | 对话模式下先问一句"要存成笔记吗"再动手；用户已经说了"整理成笔记"就等于已同意，直接写；投喂/`/learn-note` 模式直接写。 |
| 条目数靠累加 | 一律 `Glob`/`Grep` 实算，防止 INDEX 与实际漂移。 |
| 照搬对话里的 `★ Insight` 块 | 直接当速查卡用。它是现成的素材，不是要改写的草稿。 |
| 照抄模板示例里的链接 | 示例是示意。`相关：` 行只写本轮**真实出现过**的概念，没有就整行省略。 |
| 标签表把 frontmatter 也算进去 | 只数条目行尾的内联 `#tag`。frontmatter 是文件级元数据，计进去会虚增。 |

## 不做

- 检索脚本、全文索引 — `Glob` + `Grep` 够用
- subagent 代写 — 会丢掉对话上下文，而上下文正是素材本身
- 与具体研究项目挂钩 — 用户没要求，不猜
- 建空的占位条目 — 没有真素材就别开文件，等有内容再建
